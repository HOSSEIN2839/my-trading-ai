# My Trading AI

ربات پژوهشی ترید رمزارز با سه لایهٔ تصمیم‌گیری: شاخص‌های تکنیکال، تحلیل Gemini و مدل یادگیری ماشین آموزش‌دیده روی کندل‌های تاریخی.

> **حالت فقط شبیه‌سازی (Paper Trading) است.** سفارش واقعی ارسال نمی‌شود و سودآوری تضمین نیست.

## یادگیری ماشین چه می‌کند؟
- دادهٔ تاریخی را به ویژگی‌هایی مثل بازده قیمت، فاصلهٔ EMAها، RSI، ATR و تغییر حجم تبدیل می‌کند.
- بر اساس بازده سه کندل آینده در دادهٔ آموزشی، برچسب BUY / SELL / HOLD می‌سازد.
- یک مدل Random Forest آموزش می‌دهد و آن را روی بخش زمانیِ جدیدترِ داده‌ها ارزیابی می‌کند.
- خروجی مدل همراه با تحلیل تکنیکال و Gemini بررسی می‌شود؛ برای ورود، هر سه باید با هم موافق باشند.
- اگر مدل آموزش‌دیده وجود نداشته باشد، ربات شروع نمی‌شود.

**محدودیت مهم:** این هنوز یادگیری خودکار پس از هر معامله نیست. آموزش مجدد فعلاً دستی است. دقت طبقه‌بندی هم برابر با سوددهی نیست. ابزار بک‌تست هزینه‌محور اضافه شده، اما نتیجهٔ آن فقط ارزیابی یک خط‌مبنای تکنیکال روی دادهٔ تاریخی است و هنوز جایگزین walk-forward یا ارزیابی نهایی مدل ترکیبی ربات نیست.

## نصب در Windows / PowerShell
در پوشهٔ پروژه اجرا کن:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

کلید Gemini را فقط در فایل محلی `.env` وارد کن. آن را در GitHub منتشر نکن.

## آموزش مدل با دیتاست CSV محلی

فایل پیش‌فرض دیتاست باید در مسیر `data/candles_BTCUSDT_15m.csv` باشد. ستون‌های ضروری عبارت‌اند از `timestamp`, `open`, `high`, `low`, `close`, `volume`. اگر ستون‌های `symbol` و `interval` موجود باشند، با تنظیمات نماد و تایم‌فریم مقایسه می‌شوند. زمان عددی باید برحسب میلی‌ثانیهٔ Unix باشد؛ زمان‌های متنی قابل‌تبدیل به تاریخ نیز پذیرفته می‌شوند.

برای آموزش از فایل CSV محلی استفاده کن:

```powershell
python -m src.train_model
```

این دستور به API بایننس برای دریافت کندل‌ها متصل نمی‌شود و ربات را اجرا نمی‌کند. کد داده را اعتبارسنجی می‌کند، فاصله‌های زمانی غیرمنتظره را رد می‌کند و شاخص‌های EMA، RSI و ATR را از OHLCV دوباره می‌سازد؛ ستون‌های شاخص ازپیش‌محاسبه‌شدهٔ CSV استفاده نمی‌شوند. برای تعیین مسیر دیگری می‌توان متغیر `TRAIN_DATA_PATH` را در `.env` تنظیم کرد. `SYMBOL` و `TIMEFRAME` نیز باید با نماد و تایم‌فریم دیتاست هماهنگ باشند.

مدل محلی در `data/model.joblib` و گزارش ارزیابی در `data/training_report.json` ذخیره می‌شود. **اجرای آموزش فایل مدل قبلی را جایگزین می‌کند**؛ اگر لازم است آن مدل را نگه داری، پیش از آموزش از آن نسخهٔ پشتیبان بگیر. دیتاست فعلی کاربر تا ۱۶ ژوئیهٔ ۲۰۲۶ را پوشش می‌دهد؛ گزارش زمان آخرین کندل را ثبت می‌کند و قدیمی‌بودن داده را باید هنگام تفسیر نتیجه در نظر گرفت.

ابتدا مدل را آموزش بده و سپس تست‌ها را اجرا کن:

```powershell
python -m pytest -q
```

معیارهای طبقه‌بندی، تضمین سود یا جایگزین بک‌تست خالصِ هزینه‌محور نیستند.

## بک‌تست خط‌مبنای تکنیکال

برای اجرای بک‌تست خط‌مبنای تکنیکال روی کندل‌های تاریخی عمومی و ذخیرهٔ گزارش در `data/backtest_report.json` اجرا کن:

```powershell
python -m src.backtest
```

این بک‌تست سیگنال را پس از بسته‌شدن کندل محاسبه می‌کند و سفارش مجازی را در بازشدن کندل بعدی فرض می‌کند؛ کارمزد و لغزش قیمت را در ورود و خروج لحاظ می‌کند. اگر حد ضرر و حد سود هر دو در یک کندل لمس شوند، حد ضرر اول فرض می‌شود. این نسخه هنوز spread، funding، حداقل اندازه سفارش صرافی یا walk-forward چندبازه‌ای را مدل نمی‌کند.

## داده‌کاوی و کشف الگو

برای استخراج فرضیه‌های ساده از رژیم‌های بازار و ارزیابی آن‌ها روی بخش زمانیِ بعدتر، اجرا کن:

```powershell
python -m src.pattern_mining
```

گزارش در `data/pattern_report.json` ذخیره می‌شود. این ابزار ویژگی‌های بازار را به بازه‌های کمی تقسیم می‌کند، هم رژیم‌های تک‌ویژگی و هم تعامل‌های دوتایی ویژگی‌ها را می‌سنجد، جهت هر الگو را فقط از بخش آموزش می‌آموزد، افق برچسب را پیش از بخش آزمون حذف می‌کند و روی دادهٔ زمانیِ نگه‌داشته‌شده تعداد شواهد، میانگین بازده، نرخ جهت درست و کران پایین فاصلهٔ اطمینان Wilson را گزارش می‌دهد. مسیر گزارش با `PATTERN_REPORT_PATH` و تعداد کندل‌ها (بین 100 تا 1000 برای دریافت تک‌درخواستی) با `PATTERN_CANDLE_LIMIT` قابل تنظیم است.

**محدودیت مهم:** این مرحله داده‌کاوی اکتشافی است؛ الگوها به‌صورت خودکار وارد تصمیم‌های ربات یا مدل نمی‌شوند. آزمون چندین الگو می‌تواند نتیجهٔ نگه‌داشته‌شده را بیش‌ازحد خوش‌بینانه کند، و بازده close-to-close شامل کارمزد، اسپرد، لغزش قیمت یا پرشدن واقعی نیست. قبل از هر استفادهٔ تصمیم‌ساز، به دادهٔ چندسالهٔ بدون شکاف، آزمون walk-forward چندبازه‌ای، اصلاح اثر آزمون‌های متعدد و ارزیابی سود خالص هزینه‌محور نیاز است.

## رابط کاربری (Dashboard)

پس از نصب وابستگی‌ها، در ترمینال جداگانه و از پوشهٔ اصلی پروژه اجرا کن:

```powershell
python -m src.dashboard
```

سپس در مرورگر باز کن: `http://127.0.0.1:8765`

داشبورد به‌صورت خودکار هر ۱۰ ثانیه وضعیت موجودی مجازی، قیمت آخر ثبت‌شده، پوزیشن، معاملات و تصمیم‌های ذخیره‌شده را می‌خواند. این نسخه **فقط‌خواندنی** است و دکمه‌ای برای سفارش یا تغییر تنظیمات ندارد. سرویس به‌طور پیش‌فرض فقط روی رایانهٔ خودت (`127.0.0.1`) در دسترس است؛ آن را مستقیماً روی اینترنت عمومی منتشر نکن.

برای بررسی API می‌توانی مسیرهای `/api/health`، `/api/status`، `/api/integration`، `/api/trades`، `/api/decisions` و `/api/backtest` را باز کنی. داشبورد منحنی سرمایهٔ بک‌تست، شاخص‌های بازده و افت سرمایه و یک گزارش تشخیصی فقط‌خواندنی از حالت اجرا، فایل وضعیت، جدول‌های SQLite، دفتر معاملات CSV و وجود فایل مدل را نیز نمایش می‌دهد. گزارش یکپارچگی وجود و ساختار پایهٔ فایل‌ها را بررسی می‌کند؛ جایگزین اجرای کامل ربات یا اعتبارسنجی محتوای مدل نیست.

## تنظیمات
- `MODEL_PATH`: مسیر فایل مدل؛ مدل فقط در صورت تطابق ویژگی‌ها، نماد و تایم‌فریم بارگذاری می‌شود.
- `TRAIN_DATA_PATH`: مسیر دیتاست محلی برای آموزش؛ پیش‌فرض `data/candles_BTCUSDT_15m.csv`.
- `BACKTEST_REPORT_PATH`: مسیر اختیاری گزارش بک‌تست برای داشبورد.
- `MODE=paper`: تنها حالت پشتیبانی‌شده.
- `SYMBOL=BTC/USDT` و `TIMEFRAME=15m`: بازار و بازهٔ زمانی.
- `INITIAL_BALANCE=1000`: موجودی مجازی به USDT.
- `RISK_PER_TRADE=0.005`: ریسک هدف هر معاملهٔ مجازی ۰٫۵٪.
- `MAX_DAILY_LOSS=0.02`: توقف ورودهای جدید پس از زیان روزانهٔ ۲٪.
- `GEMINI_API_KEY`: کلید محلی برای تحلیل Gemini؛ بدون کلید، تحلیل AI به HOLD تبدیل می‌شود.

## ساختار
- `src/market.py`: داده و شاخص‌های تکنیکال
- `src/learning.py`: ویژگی‌ها و پیش‌بینی مدل آموزش‌دیده
- `src/train_model.py`: آموزش و ارزیابی زمانی از CSV محلی
- `src/backtest.py`: بک‌تست تاریخی هزینه‌محور برای خط‌مبنای تکنیکال
- `src/pattern_mining.py`: استخراج و ارزیابی اکتشافی الگوها با برش زمانی و حذف افق نشت
- `src/ai_analyst.py`: تحلیل Gemini و ترکیب سیگنال‌ها
- `src/risk.py`: اندازهٔ موقعیت و کنترل زیان
- `src/paper_broker.py`: شبیه‌ساز معاملات و گزارش CSV
- `src/memory.py`: حافظهٔ پایدار SQLite برای تصمیم‌ها، معاملات مجازی، الگوها، ارزیابی‌ها و نسخه‌های مدل
- `src/bot.py`: هماهنگ‌کنندهٔ حلقهٔ اصلی
- `src/paths.py`: مسیرهای مشترک و یکسان برای داده، مدل و گزارش‌ها
- `src/dashboard.py`: API فقط‌خواندنی برای رابط کاربری
- `dashboard/index.html`: داشبورد فارسی واکنش‌گرا
- `docs/ARCHITECTURE.md`: مرز مسئولیت ماژول‌ها، جریان داده و قراردادهای یکپارچگی

## معماری و یکپارچگی

هر قابلیت جدید باید مرز مسئولیت ماژول‌ها، قراردادهای داده، اثر روی ذخیره‌سازی و تست‌های وابسته را هم‌زمان به‌روزرسانی کند. رابط کاربری فقط از API خواندنی استفاده می‌کند و به منطق معامله‌گری وابستگی مستقیم ندارد. جزئیات و محدودیت‌های فعلی در [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) آمده است.

## حافظهٔ پایدار

ربات تصمیم‌ها و معاملات شبیه‌سازی‌شده را در `data/memory.sqlite3` ثبت می‌کند. این پایگاه داده محلی پس از راه‌اندازی مجدد باقی می‌ماند و از Git نادیده گرفته شده است. متغیر اختیاری `MEMORY_DB_PATH` مسیر دیگری برای آن تعیین می‌کند. این نسخه زیرساخت ذخیره‌سازی تجربه را فراهم می‌کند؛ استفادهٔ آموزشی کامل از تجربه‌ها و خودبهبوددهیِ تأییدشده هنوز نیازمند مراحل توسعه و ارزیابی بعدی است. شناسهٔ آخرین کندل پردازش‌شده نیز در وضعیت ربات ذخیره می‌شود تا پس از راه‌اندازی مجدد، تصمیم‌های تکراری کمتر شوند.

## ایمنی

این نسخه به حساب صرافی وصل نمی‌شود و پول واقعی معامله نمی‌کند. شبیه‌سازی، پرشدن سفارش، کارمزد، لغزش قیمت و شکاف بازار را به‌طور کامل بازسازی نمی‌کند. قبل از هر تصمیم برای اتصال واقعی، لازم است بک‌تست هزینه‌محور، آزمایش خارج از نمونه و اجرای آزمایشی طولانی انجام شود. کلیدهای API صرافی را در GitHub قرار نده؛ در آینده نیز مجوز برداشت باید غیرفعال باشد.
